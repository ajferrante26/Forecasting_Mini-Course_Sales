

# CNN-LSTM for Time Series Forecasting

A CNN-LSTM model for the Kaggle competition **Forecasting Mini-Course Sales**. The pipeline forecasts total daily sales with a convolutional-recurrent network, then distributes the aggregate forecast across the 75 `(country, store, product)` series using historical seasonal proportions.

## Overview

The assignment asks for a CNN-LSTM architecture applied to time series data. Convolutional layers extract local temporal features from sliding windows of the input; LSTM layers capture longer-range dependencies across the sequence. This repository delivers that architecture end to end: loading, normalization, sequence construction, training, evaluation, visualization, and a Kaggle-ready submission.

The design uses a **two-stage forecasting pipeline**:

1. **Aggregate forecast.** A CNN-LSTM predicts total daily sales across all series combined.
2. **Series allocation.** The aggregate prediction is distributed to each `(country, store, product)` series using the share observed on the same calendar day in a reference year.

This split keeps the network input univariate and easy to reason about while still producing a per-series submission. The trade-off, discussed under Limitations, is that the model does not learn per-series temporal dynamics.

## Dataset

The competition data consists of three CSV files:

| File | Contents |
|------|----------|
| `train.csv` | Daily sales for 75 series, `2017-01-01` through `2021-12-31`. Columns: `row_id`, `date`, `country`, `store`, `product`, `num_sold` |
| `test.csv` | Daily rows to forecast, `2022-01-01` through `2022-12-31`. Columns: `id`, `date`, `country`, `store`, `product` |
| `sample_submission.csv` | Expected submission schema. Columns: `id`, `num_sold` |

The 5 countries × 3 stores × 5 products combination yields 75 series, and 75 × 365 days produces the 27,375 submission rows.

The Kaggle metric for this competition is **SMAPE** (Symmetric Mean Absolute Percentage Error), where lower is better.

## Model architecture

```
Input                       (30, 1)          # 30-day sliding window
Conv1D(64, kernel=3, relu)  (30, 64)         # Local temporal features
MaxPooling1D(2)             (15, 64)
Conv1D(32, kernel=3, relu)  (15, 32)         # Higher-level features
MaxPooling1D(2)             (7, 32)
LSTM(64)                    (64)             # Sequence-level dependency
Dropout(0.2)
Dense(32, relu)
Dense(1)                                    # Next-day total sales
```

Approximately 33,000 trainable parameters. Confirm the exact count from `model.summary()` in your run.

The two `Conv1D` blocks extract short-range structure such as weekly rhythm and local momentum. `MaxPooling1D` halves the sequence length at each block, reducing computation while retaining the strongest features. The `LSTM` layer then reads the reduced feature sequence and produces a summary representation of the window. `Dropout` mitigates overfitting; the dense head produces the scalar prediction.

## Training setup

| Parameter | Value |
|-----------|-------|
| Loss | Mean Squared Error |
| Metrics | Mean Absolute Error |
| Optimizer | Adam, learning rate `0.001` |
| Batch size | 32 |
| Max epochs | 80 |
| Early stopping | `patience=8` on `val_loss`, restore best weights |
| Checkpointing | `best_model.h5` on `val_loss` |

**Validation split.** The final month of `train.csv` is held out (typically `2021-12-01` through `2021-12-31`). If that window contains fewer than 30 samples, the script falls back to a chronological 90/10 split.

**Sequence construction.** A sliding window of 30 days forms the input; the following day is the target. Inputs have shape `(samples, 30, 1)`, which is what `Conv1D` expects.

## Training process monitoring

Two figures are produced:

1. **Training curves.** Loss and MAE trajectories across epochs for train and validation sets. Early stopping triggers automatically once validation loss plateaus, so the plot shows convergence and the stopping point.
2. **Validation predictions.** Predicted versus actual daily totals for the held-out month, in real units after inverse scaling.

## Recursive forecasting

The recursive loop feeds each prediction back into the input window to forecast the next day:

```
seq = last 30 days of scaled training data
for each day in the test range:
    p = model(seq)
    seq = concat(seq[1:], p)
```

The loop covers `2022-01-01` through `2022-12-31`. Predictions are inverse-scaled with `MinMaxScaler.inverse_transform` and clipped at zero to prevent negative forecasts.

A performance note: the loop calls `model(tf.constant(seq), training=False)` rather than `model.predict(seq)` per step. The direct call avoids repeated graph retracing and produces the entire 365-day forecast in seconds rather than minutes.

## Series allocation

Each forecast date needs its total split across 75 series. The script builds a proportion lookup from a reference year:

1. Aggregate 2020 sales by date to get the daily total.
2. Divide each series' sales by that total to produce a per-`(month_day, series_id)` proportion.
3. Look up proportions for each test row by its calendar month/day and series identity.
4. Fall back to the series' overall average proportion if that specific date has no reference row.
5. Normalize per-date so proportions sum to one.
6. Multiply by the predicted daily total.

The reference year is set to `train_end.year - 1` in the current code, which resolves to **2020** for this dataset.

## Results

| Artifact | Value |
|----------|-------|
| Validation loss (MSE) | ~0.0005 |
| Validation MAE | ~0.0137 |
| Kaggle public SMAPE (2020 reference) | **43** |
| Kaggle public SMAPE (2021 reference) | 47 |

The 2020 reference produced the better leaderboard result. The 4-point swing between references, with the network unchanged, shows that the allocation step carries a large share of the total error budget for this pipeline rather than the CNN-LSTM itself. This is discussed further in the Limitations section.

## Ablation: reference year

Because only the allocation step changes between the two submissions, the 43-versus-47 comparison is a clean ablation.

- **2020 reference.** Scored 43. Wins.
- **2021 reference.** Scored 47. Four points worse.

The result suggests that series shares in 2021 were less representative of 2022 than 2020 shares were. SMAPE is harsh on low-volume series because the denominator is small, so whichever year's shares closely match 2022 for the smallest series wins the comparison, regardless of chronological proximity.

The choice is kept at 2020 for the final submission. A more rigorous selection would use an offline backtest on held-out years rather than a single leaderboard comparison; such a backtest is a natural extension but not required for the assignment deliverable.

## Limitations

- **No per-series dynamics.** The model predicts only the aggregate, so it cannot learn that some series trend differently from others. This places a ceiling on achievable SMAPE.
- **Single-year allocation reference.** Seasonal shares from a single year are sensitive to anomalies in that year. Averaging proportions across multiple non-disrupted years would reduce that noise.
- **Recursive error accumulation.** Each step consumes the previous prediction, so errors compound over the 365-day horizon. Shorter horizons or teacher forcing would mitigate this.
- **Univariate input.** Exogenous signals such as holidays, promotions, or day-of-week and month-of-year encodings could raise accuracy but are not used here.

A natural next step is a per-series CNN-LSTM with embedding layers for country, store, and product, trained jointly across the 75 series. That design allows the network to learn series-specific temporal behavior instead of allocating a shared aggregate, directly addressing the dominant limitation above.

Place the three Kaggle CSV files alongside `model.py`, then:

## Notes for future work

- Replace the aggregate-then-allocate design with a per-series CNN-LSTM using categorical embeddings for country, store, and product.
- Add calendar features (day of week, month, holiday flags) as additional input channels to `Conv1D`.
- Replace the recursive forecast with a direct multi-horizon model or a sequence-to-sequence architecture to reduce error accumulation.
- Backtest allocation reference schemes (single year, multi-year average, multi-year excluding anomalous years) on held-out data rather than a single leaderboard score.
- Run multi-seed training and average predictions to reduce variance in the aggregate forecast.
